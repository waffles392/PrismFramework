# C / C++ sources

all non-Swift code in Prism lives here. the framework (`Sources/Prism`) is pure
Swift - nothing outside these directories includes a C or C++ header.

| path | kind | notes |
|---|---|---|
| `Sources/CSDL3/` | system shim | `module.modulemap` + `shim.h` over `sdl3` (pkg-config). hand-written, 2 files. |
| `Sources/CSDL3Image/` | system shim | same, over `sdl3-image`. nothing on the Swift side imports it; it exists so `CRmlUI`'s SDL3-GPU backend gets `<SDL3_image/SDL_image.h>` from pkg-config instead of from a default include path. |
| `Sources/CFreetype/` | system shim | same, over `freetype2`. |
| `Sources/CVulkan/` | system shim | same, over `vulkan`. types only, no API calls - see the shim's comment. |
| `Sources/CRmlUI/` | hand-written + derived | Prism's C bridge (`rmlui_bridge.{cpp,h}`) and an RmlUI SDL3-GPU backend taken from RmlUI's `Backends/`. MIT - see [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). |
| `Sources/CRmlUI/src/RmlUi_SDL_GPU/ShadersCompiledSPV.h` | generated | compiled SPIR-V, consumed only by `RmlUi_Renderer_SDL_GPU.cpp`. byte-identical to RmlUI 6.3's own generated copy; produced by upstream's `compile_shaders.py`, which needs [SDL_shadercross](https://github.com/libsdl-org/SDL_shadercross). |
| `Sources/CRmlUiCore/` | vendored | RmlUI core, pinned to 6.3. 446 files, 191 `.cpp`. regenerated by `Scripts/vendor_rmlui.py`; never edit by hand. |
| `Sources/CSoloud/` | hand-written + generated | the SoLoud C API Swift imports: `shim.h`, `module.modulemap`, and `soloud_c.h` (SoLoud's generated API, trimmed - see `CSoloudCore`). Prism's own `soloud_bridge.{cpp,h}` adds the EQ filter and uniform filter introspection, which SoLoud's C API leaves out. zlib/libpng - see [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). |
| `Sources/CSoloudCore/` | vendored | SoLoud, pinned to commit `e82fd32c1f62`. 79 files. regenerated by `Scripts/vendor_soloud.py`; never edit by hand. compiled by SwiftPM, but only ever reached through `CSoloud`. |

the system shims are just glue so Swift can `import CSDL3` / `CFreetype` /
`CVulkan`; the real headers and libraries come from the system packages.
RmlUI and SoLoud are the opposite: source is vendored and compiled by SwiftPM,
because no prebuilt archive or CMake step is used.

`soloud_c.h` is the one header that crosses from a vendored target into a shim.
it is plain C, but including it from `CSoloudCore` would make clang try to build
that C++ target as C, so `Scripts/vendor_soloud.py` writes it into `CSoloud`
instead. the script also trims the audio sources the framework does not use out of
it, and out of `soloud_c.cpp`.

## Why these are targets, not a package

the C targets are declared in the **root** `Package.swift`, not in a
`Package.swift` of their own. SwiftPM forbids a package consumed by URL from
depending on a local `path:` package, so a nested package here would make
`.package(url:exact:)` fail for consumers with:

> required using a stable-version but depends on an unstable-version package

keeping them as targets of the root package preserves both the file layout and
URL consumption.

## Commands (run from the repo root)

```sh
python3 Scripts/vendor_rmlui.py          # re-fetch vendored RmlUI (tag + SHA-256)
python3 Scripts/vendor_rmlui.py --check  # verify CRmlUiCore matches the pin
python3 Scripts/vendor_soloud.py         # re-fetch vendored SoLoud (commit + SHA-256)
python3 Scripts/vendor_soloud.py --check # verify CSoloudCore matches the pin
```
